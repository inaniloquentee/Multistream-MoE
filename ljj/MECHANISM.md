# H20 机制排查：为什么表达能力增加却没有质量收益

2026-10-27，在同一固定 FineWeb-Edu Parquet shard、Qwen3-0.6B-Base checkpoint、Transformers fork 和 H20-3e `vllm-sgp-h20-03` 上做两项**探索性**实验。Slurm 作业 `2935`（`COMPLETED 0:0`，`00:06:44`）重现种子 42 的原始 D，末步完整 128 窗口 NLL `3.1281618`，与先前日志一致；作业 `2938`（`COMPLETED 0:0`，`00:12:45`）用同种子和窗口成对训练增强流对比的 C/D。两项仍是 1,000 步、batch 2、seq 128、256,000 训练 token、100 步预热、`1e-5` 余弦学习率和 BF16；除初始化流对比外不改模型和训练日程。原始 JSONL 与作业日志在 `evidence/h20-2026-10-27/mechanism/`，脚本为 `scripts/run_qwen_diagnostics.sh` 和 `scripts/run_qwen_contrast.sh`。数据、模型及框架提交与 `RESULTS.md` 固定快照实验相同。

## 可检验的机制

对任意两专家，读取系数的流维和均为 1，因此

```math
a_j X-a_k X=\sum_s(a_{j,s}-a_{k,s})(X_s-\bar X).
```

初始流完全相同，使第一个 MoE 的读取权重梯度严格为零；后续独立读取必须同时依赖流差异和专家读权重差。标准初始化的写回系数为 `[1.03,0.99,0.99,0.99]`。干预只将其改成 `[1.6,0.8,0.8,0.8]`，均值仍为 1，各专家初值仍相同；小配置测试和真实 checkpoint 的 FP32 lift 检查分别通过，增强组的最大初始 logits 差约 `8.96e-5`。C/D 的 BF16 起点 NLL 完全相同。

| 初始化 | C step 0 / 1000 NLL | D step 0 / 1000 NLL | D-C 末步 | D 最终流中心化 RMS | D 第二个 MoE 首步读取梯度 RMS |
|---|---:|---:|---:|---:|---:|
| 原始 `c=0.01` | `3.096068 / 3.128224` | `3.096068 / 3.128162` | `-0.000062` | `0.3363` | `3.51e-5` |
| 高对比 `c=0.20` | `3.096336 / 3.128122` | `3.096336 / 3.128414` | `+0.000292` | `6.3627` | `6.82e-4` |

首步第二个 MoE 的读取梯度增大约 19 倍；对应写回梯度约为 `1.27e-3`（原始）和 `1.12e-3`（高对比）。但 D-C 并未改善，高对比 D 反而略差；所有训练后 NLL 仍高于各自 step 0。这排除了“仅因初始流差异过小而完全无读取梯度”这个**单一**解释，不说明更长训练或别的实现也无效。两种初始化的 D-C 差距都小于原始三种子实验的波动，不应从一粒种子推显著性。

## 激活与低精度

在同一个固定验证 batch 的各 MoE 入口，记录实际专家读输出 RMS 和由流激活以 FP32 解析计算的读信号。下表为训练后 D 的第 3/15/27 层（从 0 编号）；第 1 层流差和读信号均为零。

| 对比 `c` / MoE 层 | 输入流中心化 RMS | FP32 读信号 RMS | BF16 实际读差 RMS | BF16 专家读输出逐元素完全相同 |
|---|---:|---:|---:|---:|
| 0.01 / 3 | `0.00303` | FP32 前向 `2.53e-5` | `0.00214` | `65.9%` |
| 0.01 / 15 | `0.01358` | FP32 前向 `9.46e-5` | `0.06298` | `65.3%` |
| 0.01 / 27 | `0.12095` | FP32 前向 `6.86e-4` | `0.06212` | `75.1%` |
| 0.20 / 3 | `0.06078` | 同激活 `4.93e-4` | `0.04489` | `53.6%` |
| 0.20 / 15 | `0.26485` | 同激活 `0.00135` | `0.00755` | `60.3%` |
| 0.20 / 27 | `2.33015` | 同激活 `0.01797` | `0.05871` | `61.9%` |

原始实验的 FP32 读信号使用另一次 FP32 前向，和 BF16 流激活并非完全相同；高对比实验新增的 `read_signal_fp32_same_input_rms` 则固定 BF16 路径的流激活。高对比第 3 层的 BF16 读差比同激活解析信号大约 91 倍，而且超过一半元素恰好相等，说明该路径受 BF16 量化台阶强烈影响；它不是“专家已经学到大量不同信息”的证据。后层真实信号有所增大，但不能由激活差异直接推断验证收益。

## 同一模型的因果消融

在**同一个训练后 D 模型、同一窗口**上临时绑定所有专家的读取权重/偏置为均值（模拟 C 的共享读取），或者将读取权重/偏置清零（均匀读取）；评估后恢复原值。正 `delta NLL` 意味着原独立读取更好。BF16 使用 32 个窗口（8,192 token），FP32 使用其中 8 个窗口（2,048 token）；区间是窗口差值的 `mean ± 1.96 SE`，不是独立训练种子的置信区间，也不是全量验证。

| 初始化 / 精度 | 绑定读取的配对 delta NLL [窗口区间] | 均匀读取 delta NLL |
|---|---:|---:|
| 0.01 / BF16 | `-0.000184 [-0.001108,+0.000740]` | `-0.000219` |
| 0.01 / FP32 | `+0.0000013 [-0.0000012,+0.0000037]` | `+0.0000104` |
| 0.20 / BF16 | `+0.000524 [-0.000297,+0.001345]` | `+0.000231` |
| 0.20 / FP32 | `+0.000028 [-0.000018,+0.000074]` | `+0.000149` |

所有绑定读取区间都跨零。路由负载在所探测 batch 的后层仍分布于四专家，例如原始末层约 `[0.22,0.15,0.36,0.27]`，未观察到简单的“只剩单一专家”现象；这不是全训练路由统计。

## 解释边界和下一步

D 在参数空间包含 C，只是表达能力关系，不保证 AdamW 在短预算、小验证采样和 BF16 下找到更好的泛化解。每个 MoE 的五个专家从同一个 dense MLP 复制，训练预算仅 256,000 token；强 dense 锚点与 A/B/C/D 全部验证退化也说明训练设定本身没有建立有效的质量改善。首层结构性零梯度、很小的有效读信号以及低精度数值效应共同削弱了这个 warm-start 实现的新增自由度；高对比仍无优势，说明不能把全部负结果归咎于初始信号弱。

这些消融支持“当前独立读取对预测贡献很小”，不能单独证明究竟是优化、数值精度、数据预算还是任务本身造成。下一项有判别力的实验是固定 C/D 配对、只将读取权重与加权求和的累积改为 FP32，再配合更长训练、保存 checkpoint、完整验证和多种子复验。当前不应启动专用 EP/kernel 性能工作。
