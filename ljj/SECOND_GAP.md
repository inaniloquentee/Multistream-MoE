# 第二处断点：有效读取不等于目标收益

这是对 `FIRST_GAP.md` 的**受控修复尝试**，不是新架构优于强基线的结论。第一处是算法/初始化问题：已有流差，但 D 的全部专家读映射初值相同。这里仅为 D 新增可选 `--initial-expert-read-contrast`，不改 Qwen/Transformers 的实现或 GPU kernel。代码、测试和 Slurm 脚本分别在 `experiments/qwen_diagnostics.py`、`experiments/train_qwen.py`、`tests/test_qwen_diagnostics.py`、`scripts/run_qwen_read_init.sh`。默认值仍为零，保留原有实验。原始 H20 JSONL 和作业日志在 `evidence/h20-2026-10-27/read-init/`。

## 修复第一处断点

写回仍取 `c=0.2`，即 `[1.6,0.8,0.8,0.8]`、均值为一。在每个 MoE 中保留共享专家的均匀读取，四个路由专家的初始读 logits 分别取 `[-1,-1/3,+1/3,+1] * 0.25 * [3,-1,-1,-1]`。此方向对应当前 warm-start 真正出现的一维流差；`read_weight` 仍为零，参数和训练日程未变。单元测试检查第二个 MoE 专家输入分离、首个 MoE 仅有舍入误差，并且初始化失败不会部分改写别的层。

**不能把干预后的模型称为精确 Qwen lift。** 干预前对真实 checkpoint 的 8-token FP32 lift 最大 logits 差 `8.96e-5`；施加读偏置后，与原 Qwen 的最大差升至 `0.6109`。相同 128 个固定验证窗口的 BF16 step 0 NLL 从零读偏置的 `3.096336` 变为 `3.096810`。这是必须报告的起点变化，不能仅比较末步损失。

Slurm `2945` 在 `vllm-sgp-h20-03` 上完成（`COMPLETED 0:0`，`00:07:07`），10 个单元测试在后续复核通过。step 0 的第 3 层（第二个 MoE）读输入，实际 BF16 专家-共享 RMS 差 `0.019865`，同激活 FP32 解析差 `0.019433`；第一层仍为零。**第一处零信号确实被修复**，并且不是仅在离线玩具反例上成立。

## 同预算结果

全部使用同一个固定 Qwen3-0.6B-Base、FineWeb-Edu shard、Transformers fork、seed 42、batch 2、seq 128、1000 步/100 步预热、128 个固定验证窗口和 BF16。前两行是 `MECHANISM.md` 中既有的成对对照；第三行只改变 D 的读初始化。

| 模型 | step 0 NLL | step 1000 NLL | 相对同设置 C 的末步差 |
|---|---:|---:|---:|
| C，零读偏置 | 3.096336 | 3.128122 | 0 |
| D，零读偏置 | 3.096336 | 3.128414 | +0.000292 |
| D，专家读偏置 0.25 | 3.096810 | 3.128963 | +0.000841 |

本次 D 的第 3 层首步读权重梯度 RMS 为 `6.51e-4`（旧高流对比 D 为 `6.82e-4`），不是梯度进一步增强的证据。1000 步后第 3 层 BF16 实际读差 `0.04860`、同激活 FP32 解析差 `0.01852`，仍有数值放大；独立读取也没有转化为明确的目标改进。同一模型末步暂时绑定专家读映射的 32 窗口 NLL 差（绑定后减原模型）为 BF16 `-0.000330 ± 0.001112`、FP32 `-0.000957 ± 0.002107`（`1.96 *` 窗口 SE）。两者区间均跨零；FP32 没有揭示被 BF16 完全掩盖的确定性收益。

## 第二处理论到实验差异

理论的 `F_C ⊆ F_D` 和构造性平方函数反例只说明**存在**可利用某些流差的目标及参数；它没有约束当前语料的下一 token 目标与这条读方向的相关性，也没有保证此初始化或 256,000 token 的 AdamW 优化找到更好的解。因此第一处修好之后，第二道门槛是**有效的专家差异能否对真实预测目标产生稳定的边际收益**，而不是模型能否在激活里读出差异。

`experiments/probe_initial_read_direction.py` 在完全相同的未训练 D、固定路由和写回、相同验证窗口上扫描零、正负 `0.05`、正负 `0.25` 的初始读偏置；`scripts/run_initial_read_direction.sh` 的 H20 作业 `2948` 完成（`COMPLETED 0:0`，`00:01:36`）。BF16 的 128 窗口结果相对零偏置为 `-0.000033`、`+0.000176`、`+0.000670`、`+0.000474` NLL（顺序 `-0.05,+0.05,-0.25,+0.25`；正数更差）。单项窗口 SE 约 `0.00027–0.00036`。同样的**前 32 个窗口**在两种精度下的配对差如下，不能与 128 窗口的值直接相减：

| 读偏置系数 | BF16，32 窗口相对零偏置 NLL | FP32，同 32 窗口相对零偏置 NLL |
|---:|---:|---:|
| -0.05 | +0.000799 | +0.000169 |
| +0.05 | +0.000728 | -0.000110 |
| -0.25 | +0.001280 | +0.001471 |
| +0.25 | +0.001069 | -0.000019 |

`+0.25` 的精度差约 `0.00109`，但其 BF16 和 FP32 窗口 SE 分别为 `0.000775` 和 `0.000420`；全模型 autocast 同时改变其他计算，不能据此把差异唯一归因于 MoE 读 kernel。即使 FP32 下这个方向也没有稳定的 NLL 收益。扫描不是针对所有可学读取的反证，且尝试多种强度不能当作独立显著性检验；当前预设方向未显示可靠的目标优势。**下一处可观测偏差**是低精度前向与 FP32 的有效读差/边际损失不一致，而更根本的“自然语言目标是否需要这条流方向”仍未被证明。

目前应优先将理论能力、目标对齐和有限预算优化区分开：下一项实验是用**训练窗口**估计读方向梯度，然后仅在独立验证窗口衡量其实际收益，预注册多种子完整验证；若存在一致目标收益但 BF16 无法兑现，再对共享和独立读取做配对 FP32 累积/训练干预。现有证据不足以启动专门的 EP/kernel 工作，也不足以宣称整个 D 架构无效。
