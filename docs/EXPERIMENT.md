# 实验方案

## 1. 四组对照

| 组别 | 结构 | 目的 |
|---|---|---|
| A | 普通共享专家 MoE，单残差流 | 原始基线 |
| B | mHC 式 4 流，所有专家共享读取和写回映射 | 分离多流本身的收益 |
| C | 4 流，共享读取，专家独立写回 | 分离写回收益 |
| D | 4 流，专家独立读取和写回 | 验证核心假设 |

B/C/D 使用相同的残差混合、注意力结构和初始化策略；仅改变 MoE 读写映射的共享方式。独立映射由共享映射克隆初始化，并检查初始前向一致。此处是受控的 mHC 式实现，不宣称完整复现已发表模型。

每个 token 的状态为 $X\in\mathbb{R}^{4\times d}$，D 组采用：

$$
X^+=R(X)X+b_sE_s(a_sX)+\sum_{j\in S(X)}g_jb_jE_j(a_jX).
$$

$a_j$ 为读取行向量，$b_j$ 为写回列向量。所有组的路由器均读取公共均值；门控在选中的专家内归一化。共享专家与路由专家并行读取旧状态，多流结果保留到下一层。

残差混合统一采用 $R=0.95I+0.05Q$，其中 $Q$ 由同一 Sinkhorn 实现产生。记录行列和偏差，超过 $10^{-4}$ 则修复实现；不把近似双随机当成完整梯度稳定保证。

## 2. 固定配置

| 项目 | 首轮设置 |
|---|---|
| 模型 | 12 层、隐藏维度 512、8 个注意力头、词表 32,000、输入输出嵌入共享 |
| 前馈层 | 偶数层为 MoE，共 6 层；其余为稠密 SwiGLU，中间维度 1,536 |
| 专家 | 每个 MoE 层 1 个共享＋8 个路由专家，Top-2；专家中间维度 768 |
| 训练 | BF16、序列长 1,024、全局每步 32,768 个有效 token |
| 优化器 | AdamW，学习率 3e-4，betas=(0.9,0.95)，eps=1e-8，权重衰减 0.1，梯度裁剪 1 |
| 调度 | 前 10% 步数预热，随后余弦衰减至 3e-5；同一轮各组完全一致 |
| 负载均衡 | 同一辅助损失实现与系数 0.01；参考版本不丢 token，记录专家负载 |
| 首轮预算 | 每组 1,000 步＝32,768,000 token；种子 42；四组共 131,072,000 token |
| 扩展预算 | 确认资源后，每组 10,000 步，种子 42/43/44；四组共约 39.32 亿 token |

参数规模约一亿级，仅为估计；实施时统计实际总参数、激活参数及读写映射开销。相同 token 预算不等于相同 FLOPs 或 GPU 时间。

数据：FineWeb-Edu 的 sample-10BT 子集，流式读取固定分片；使用 TinyLlama 分词器。启动前记录数据及分词器修订号、文档标识、划分和样本顺序。按文档划分互斥训练/验证集，并检查重复；固定约 200 万验证 token。各组不得更换分片或分词器。

## 3. 硬件与正确性

- 单卡：固定路由索引的小张量梯度检查；BF16 前向/反向误差对照；32 步无 NaN/Inf。
- 4/8 卡：按资源设置 EP=4/8、TP=1；全局有效 token 数保持一致，差额用梯度累积调整。
- 多流保留在 token 所属设备，首版在本地生成专家输入，再派发；回传后按专家分别写回。
- 不得在专家特定写回之前盲目合并专家输出。通信反向必须覆盖输入、读取、写回和门控的梯度。
- 记录 GPU 型号/数量/显存、拓扑、驱动、CUDA、PyTorch、NCCL、通信后端和代码提交号。没有跨机资源就不报告跨机收益。

## 4. 指标与决策

- 每 100 步评估验证负对数似然；同时记录有效 token/s、GPU 时、峰值显存、梯度范数、专家负载和流间相似度。
- 主比较：D 对 B/C。首轮只有排错和探索意义，不以单种子短训宣称有效。
- 扩展轮预设信号：相对 B/C，3 个种子方向一致、平均改善至少 0.01 nats/token；报告全部结果与波动，不等同于统计显著性证明。
- 另外比较验证损失随累计 GPU 时的曲线及达到同一损失的成本；未达到的目标记为未达到，不外推。
- 通信优化以全训练步为准：预热 30 步、测量 100 步、重复 3 次；报告中位数和波动。目标是吞吐提升至少 10%，不降低数值正确性。
- 对照组使用相同的通用融合、重叠和精度配置；另行隔离架构专用优化的贡献。

## 5. 优先排查的通信问题

1. 专家输入不同后，原有 token 去重是否失效？同时记录真实发送字节数与派发/回传耗时。
2. 专家独立写回是否阻止原有回传归并？以参考实现验证，不能为提速改变语义。
3. 先融合读取混合与打包、回传与写回；只有剖析证明必要，才探索目的端公共基底复用。
4. 保持共享专家与路由分支无本层先后依赖，检查能否与通信重叠。
